# 論述查核方法

## 1. 抽出可查核的說法
從逐字稿挑出「撐起影片論點」的事實陳述：數字、日期、人名、引述、因果關係、研究結論、規格、價格。每則記下時間戳與原話（原文語言、短句即可）。

不查的東西：
- 價值判斷與預測（「這是最好的政策」「明年一定漲」）：表格中判定填「觀點」，並說明它依據了哪些事實。
- 創作中的虛構情節、玩笑、誇飾。

## 2. 查證
- 每則至少找一個**一手或權威來源**：官方統計、法規原文、論文、公司公告、主要媒體的原始報導。用 `web_search` 找、`web_fetch` 打開讀原文，不要只看搜尋摘要。
- 重要或有爭議的說法找**第二個獨立來源**互相印證。
- 注意時間：影片發布日期與現在不同，標明「發布時正確、現已改變」。
- 科學與醫療優先找系統性回顧與官方指引，不要用單一研究推翻共識。

## 3. 判定（表格的「判定」欄只能用這些詞）
| 判定 | 意思 |
|---|---|
| 正確 | 與可靠來源一致 |
| 大致正確 | 主旨正確，細節或數字有小出入 |
| 部分正確 | 有對有錯，或只對一部分情況成立 |
| 缺乏脈絡 | 事實本身對，但少了會改變理解的背景 |
| 誤導 | 用真實資訊導向錯誤結論，或誇大 |
| 錯誤 | 與可靠來源矛盾 |
| 無法查證 | 找不到可靠來源證實或否定（寫出查過哪裡） |
| 觀點 | 價值判斷或預測，不適用真偽 |

## 4. 表格格式
```
| # | 時間 | 影片中的說法 | 判定 | 查核說明 | 來源 |
|---|---|---|---|---|---|
| 1 | [03:35](https://www.youtube.com/watch?v=ID&t=215s) | 「輸入層有 784 個神經元」 | 正確 | 28×28 像素的 MNIST 影像，每個像素一個輸入 | [MNIST](http://yann.lecun.com/exdb/mnist/) |
```
- 除了「無法查證」與「觀點」，每列都要有來源連結。
- 表格之後寫一段「整體評估」：影片的論述整體可信度、最大的問題在哪、對觀眾理解的影響。並在 `cover.json` 的 `verdict` 填整體判定（`tone`: ok 正確/大致正確、warn 部分正確/缺乏脈絡/無法查證、err 誤導/錯誤）。

## 5. 公平與謹慎
- 先找最有利於講者的解讀，再判定。
- 不臆測動機；利益衝突只寫可查證的事實（業配標示、頻道自述、公開持股）。
- 健康與財經內容加上免責說明（見分類說明）。
