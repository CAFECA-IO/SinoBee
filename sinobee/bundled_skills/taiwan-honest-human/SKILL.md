# 臺灣在地化、專業潤稿與查證

> 本技能由 CAFECA 為 SinoBee 撰寫，MIT 授權。`scripts/data/s2t.json` 取自 OpenCC 字典（Apache-2.0，見
> `scripts/data/OPENCC-LICENSE`）；用語對照表與寫作規則為 CAFECA 依教育部、國家教育研究院與中華語文知識庫
> 的資料整理，參考來源列於文末。

把一段中文改成臺灣讀者讀起來自然、可信、專業的文字。三件事缺一不可：

1. **字與詞是臺灣的**：正體字、臺灣用語、臺灣的標點與書寫慣例。
2. **語氣是專業的人寫的**：具體、精準、不空泛，沒有口號、套話與行銷形容詞。
3. **內容是誠實的**：事實、數字、引述都查過；查不到的明說查不到，絕不編造來源。

## 不改的東西

- **原意**：只改寫法，不增刪論點，不替作者下結論。若原文有錯，修正並在查證紀錄說明，不悄悄改掉。
- **直接引語**：引號內是某人說過的話，用詞照原話（簡體可轉正體），需要時加註說明。
- **專有名詞**：公司、品牌、產品、法規、機關、書名、人名依其正式名稱（例：台積電登記名稱為「台灣積體電路製造股份
  有限公司」，不改成「臺」；《臺灣地區與大陸地區人民關係條例》不改成「台灣」）。
- **程式碼、指令、網址、檔名、介面上實際顯示的文字**（工具會自動略過程式碼區塊、行內程式碼與網址）。
- **另一地區的事實**：大陸的制度、法規、貨幣、機構照實寫（人民幣、醫保、高考），必要時加一句說明，不換成臺灣制度。

## 流程

### 1. 確認範圍

先看文字的用途與讀者：新聞稿、技術文件、對外簡報、行銷文案、學術報告、公文或內部信件。
以下有預設值，只有真的不確定、而且影響結果時才用 `ask_user` 問一次：

| 項目 | 預設 |
|---|---|
| 交付方式 | 另存新檔（`<原檔名>.tw.md`），不覆蓋原檔 |
| 「台」或「臺」 | 沿用原文多數的寫法；原文沒有偏好時，正式文件用「臺」（教育部字典以「臺」為正字、「台」為異體），專有名詞照登記名稱 |
| 年份 | 沿用原文；政府公文用民國紀年，其餘用西元，同一份文件不混用 |
| 中英文之間的空格 | 沿用原文；原文沒有慣例時，整份文件統一一種做法（中文與英文、數字之間加或不加半形空格都可以，不要混用） |
| 查證深度 | 每一個可查證的事實都查（見步驟 5）；使用者說「只改用語」時，查證只做明顯有疑問的部分並說明 |

### 2. 機械檢查與安全修正

```
skill_run(name="taiwan-honest-human", args="check '<檔案>'")
skill_run(name="taiwan-honest-human", args="fix '<檔案>' '<檔案>.tw.md'")
```

路徑一律用單引號包住。內容不在檔案裡時，先用 `write_file` 存成工作區的暫存檔。

`fix` 只做不需要判斷的事：

- 只有一個正體寫法的簡體字。
- 標為 R、且只有一個臺灣用語的詞（軟件→軟體、服務器→伺服器、人工智能→人工智慧）。
- 中文旁的半形標點，以及引號改成「」『』。

其餘項目只列出位置，由你判斷：

| 報告欄位 | 意思 | 你要做的事 |
|---|---|---|
| `multi_form_guesses` / `multi` | 一個簡體字有多個正體（发→發／髮、里→裡／里、台→臺／颱）。工具先依詞組判斷，判斷不了才用最常見的寫法 | 看上下文確認每一個，錯了就改 |
| `suggest` | 大陸用語，臺灣用語有兩種以上（視頻→影片／視訊、信息→資訊／訊息） | 依語境選一個 |
| `review` | 臺灣也有這個詞但意思不同（支持／支援、項目／專案、質量／品質、通過／透過、程序／程式） | 依說明欄判斷要不要改 |
| `region` | 「國內、我國、內地、大陸」等地域稱呼，只在大陸來源的文字出現 | 寫清楚指哪裡（例：大陸文本的「國內」改為「中國大陸」），涉及立場時保留原文並告訴使用者 |
| `tw_variant` | 非臺灣標準的異體字（爲、裏、着） | 改成臺灣寫法 |
| `style` | 空泛或像 AI 寫的句型 | 步驟 4 處理 |
| `tai` | 「台」「臺」混用 | 統一（專有名詞除外） |

查單一個詞：`skill_run(name="taiwan-honest-human", args="terms '軟件'")`。

### 3. 用語：工具抓不到的部分

對照表只涵蓋常見的詞。改寫時另外注意：

- **語序與搭配**：「進行一個討論」→「討論」；「做一個分享」→「分享」；「把…給…」等口語結構改成書面語。
- **大陸職場與政策行話**（賦能、抓手、閉環、打通、對齊、顆粒度、復盤、底層邏輯、頂層設計）：改成具體的動作或結果，
  不要換成另一個流行語。
- **稱呼**：「小伙伴」→「同仁、夥伴」；「親」「寶寶們」等網路稱呼在正式文字中刪除。
- **外國譯名**：人名、地名、機構名以臺灣通行譯名為準。不確定時，查中央社或外交部網站上的用法，並在第一次出現時附原文。
- **專業術語**：以國家教育研究院「樂詞網」公告的學術名詞為準（例：algorithm 譯為演算法）。

### 4. 改寫成專業、自然的語氣

完整規則與前後對照範例見 `references/style-guide.md`。重點如下：

- **先講結論，再講根據**：每段第一句就是該段要點。
- **具體取代形容**：「大幅提升效率」→「處理時間從 12 分鐘縮短為 3 分鐘」。沒有數字就不要誇大。
- **刪掉預告與套話**：值得注意的是、總而言之、在當今時代、隨著…的發展、讓我們一起…、希望對你有幫助。
- **少用驚嘆號、表情符號與粗體**；破折號不連續使用；不要每段都是「首先、其次、最後」。
- **主詞清楚、動詞有力**：「被廣泛應用於」→「用於」；「進行優化」→「改善」。
- **稱謂與敬語依對象而定**：對外正式信件可用「敬請、惠予、謹此」，內部溝通不需要；不同對象不要混用。

### 5. 查證論述

逐條列出可查證的陳述：數字、日期、人名職稱、機構名稱、法規條文、引述、排名、因果關係、「第一個／唯一」這類說法。
有 `web_search` 與 `web_fetch` 就查，方法與臺灣常用的第一手來源見 `references/fact-check.md`。

每一條標成以下其中一種：

- ✅ **已查證**：附上來源名稱、網址與查閱日期。
- ✏️ **已更正**：原文錯在哪、正確內容是什麼、來源為何。
- ⚠️ **有爭議或過時**：來源之間不一致，或資料已經更新。在文中寫出年份或「依某某資料」。
- ❓ **查不到**：文中改用保留的寫法（「據某某表示」），或刪除後告訴使用者，不可寫成確定的事實。

規則：

- **不編造來源、網址、數字或引述**。查不到就是查不到。
- **優先使用第一手來源**（政府機關、法規資料庫、公司公告、原始論文）；新聞與百科只用來找線索。
- **有時效性的資料**（人口、匯率、股價、職位、法規修正）要寫出資料時間。
- 沒有網路工具時，所有項目標為 ❓，並告訴使用者需要查證哪些地方。

### 6. 最後檢查與交付

再跑一次 `check '<改好的檔案>'`：

- `simplified`、`replace`、`punctuation` 應為 0。
- 其他項目逐一確認，刻意保留的寫在修改摘要裡。

交付三樣東西：

1. **改好的文字**（存成新檔）。
2. **修改摘要**：用語、語氣、結構各改了什麼，刻意保留了什麼、為什麼。條列，十行以內。
3. **查證紀錄**：一張表，欄位為「陳述、結果（✅✏️⚠️❓）、來源與日期」。

## 注意事項

- 「支持」「項目」「質量」「通過」「程序」「文件」「數據」在臺灣也是正常用詞，不可一律替換。工具把它們列為
  `review`，正是為了讓你看上下文決定。
- 「台灣地區」在臺灣的法律語境有特定意義；「國內、我國」在大陸文本指中國大陸。這些涉及立場的稱呼，改寫前先
  確認使用者的意圖，不確定就保留原文並說明。
- OpenCC 的 `tw` 異體表與教育部的標準不完全一致（例：教育部字典以「祕」為正，OpenCC 用「秘」）。工具只提示、
  不自動改；正式文件以教育部《國語辭典》為準。
- 對照表是常用詞，不是完整的兩岸詞典。遇到沒把握的詞，查教育部《國語辭典》或中華語文知識庫。
- 這個技能不做翻譯品質認證，也不提供法律文件的正式譯本；遇到合約、判決等文件，提醒使用者交給專業譯者或律師確認。
